# Translatte

Offline photo translation: snap a sign or menu and see it overlaid in your language. Models run fully on device.
Design: `docs/superpowers/specs/2026-10-19-translatte-design.md`.

## Layout

- `core/`: Rust pipeline (OCR via NCNN, translation via bergamot-translator, layout, style hints)
- `bergamot/`: bergamot-translator (Mozilla's translations engine on Marian, MPL-2.0) vendored in `vendor/` with our patches in `patches/` (regenerate with `bergamot/vendor.sh`), a C shim and a safe Rust wrapper
- `cli/`: dev CLI (`translatte fetch|run|langs|eval`)
- `ffi/`: UniFFI bindings over the core (`Engine`) for the native apps
- `ios/`: SwiftUI iPhone app (XcodeGen project in `ios/project.yml`)
- `android/`: Kotlin/Compose Android app (Gradle project)
- `models/manifest.json`: model files (sizes), upstream repos/revisions, languages (generated by `scripts/gen_manifest.py`)
- `fixtures/`: smoke fixture; real OCR photos are fetched into `fixtures-cache/`

## Setup

Requires Rust (stable + nightly for fmt), `cmake`, `ninja` and `sccache` (`brew install cmake ninja sccache`); `uv` for the scripts. bergamot-translator builds from source through CMake (a few minutes the first time); `.cargo/config.toml` routes it through Ninja and sccache.

```bash
cargo run -p translatte-cli --release -- fetch --langs fr,ja   # or --all (~1.8GB) into models-cache/
```

`fetch` downloads the detector plus the language packs (OCR script pack and translation model) of the requested source languages (`--langs fr,ja` or `--all`) straight from the Hugging Face repos pinned in the manifest. Integrity is left to hf-hub (TLS, and hf-xet's chunk hashes for Xet-backed files); files are checked by size only. It skips files already installed (present with the expected size), and resumes interrupted downloads from their `.part` files (tagged with the upstream file, so a replaced model's partial download is never resumed). It first removes what the manifest no longer describes (dropped packs, wrong-size files such as a replaced model, stale `.part` files), as the apps do on launch (`Engine::prune_models`). `HF_ENDPOINT` and `HF_TOKEN` are honored. To bump an upstream revision, edit `REVISIONS` in `scripts/gen_manifest.py` and run `uv run scripts/gen_manifest.py`.

OCR uses PaddleOCR's PP-OCRv5 mobile detector and per-script recognizers, run with NCNN. The models are converted
from PaddlePaddle's ONNX files (at the revisions pinned in `scripts/gen_manifest.py`) by
`uv run scripts/convert_ocr_ncnn.py` and published to
[`assafvayner/translatte-ocr-ncnn`](https://huggingface.co/assafvayner/translatte-ocr-ncnn); each recognizer's
`dict.txt` still comes from its PaddlePaddle repo. Photos run them at fp32 and live frames at fp16; the CLI's `run`,
`eval` and `bench` take `--precision fp32|fp16` (default fp32).

Translation uses Mozilla's [translations](https://github.com/mozilla/translations) models (MPL-2.0): one small
int8 Marian model per source language into English, run with bergamot-translator. Every xx→en and en→xx pair is
mirrored unmodified to [`assafvayner/translatte-pair-models`](https://huggingface.co/assafvayner/translatte-pair-models)
(`scripts/build_pair_models_upstream.py` picks the releases, `scripts/mirror_pair_models.py` stages them). The
manifest lists the 52 languages that a PP-OCRv5 script pack can read and that have a model (Traditional Chinese and
Cantonese share the zh-Hant one; Serbian is Latin script only); everything is translated into English. Adding a
language or swapping a script pack is a data change in `scripts/gen_manifest.py`; check a recognizer's alphabet
coverage first with `scripts/ocr_coverage.py`.

## Usage

```bash
cargo run -p translatte-cli --release -- langs
cargo run -p translatte-cli --release -- run photo.jpg --from ja -o out/photo_en.png
cargo run -p translatte-cli --release -- run photo.jpg --from ja --no-translate   # OCR only
cargo run -p translatte-cli --release -- eval fixtures --max-cer 0.15
```

`run` writes the overlay PNG (`-o`) and prints JSON (or writes it with `--json`). The output is a `PipelineOutput { regions, translation_error }`:

```json
{
  "regions": [
    {
      "quad": [{ "x": 10.0, "y": 10.0 }, { "x": 90.0, "y": 10.0 }, { "x": 90.0, "y": 30.0 }, { "x": 10.0, "y": 30.0 }],
      "source_text": "...",
      "translated_text": "...",
      "bg_rgb": [255, 255, 255],
      "fg_rgb": [0, 0, 0],
      "angle": 0.0
    }
  ],
  "translation_error": null
}
```

`quad` lists the corners clockwise from the top-left.

With `--no-translate` the translation model is not loaded, `translated_text` is null, and the PNG is the input photo with the detected text boxes outlined in red instead of a translation overlay.

If translation fails, OCR results are kept: `translated_text` is absent/null, `translation_error` is set, and the error is printed to stderr.

`eval` scores OCR only and prints per-language mean CER. The metric is recall-oriented (extra recognized lines are not penalized) and exits non-zero if no fixtures are found when `--max-cer` is set. Real scene-text photos are downloaded on demand (`uv run scripts/fetch_fixtures.py`, then `eval fixtures-cache`); see `fixtures/README.md`.

## iOS app (simulator)

Requires Xcode with an iOS Simulator runtime (`xcodebuild -downloadPlatform iOS`), `xcodegen`
(`brew install xcodegen`), and the Rust iOS targets (`rustup target add aarch64-apple-ios aarch64-apple-ios-sim`).

```bash
scripts/ios/build-rust.sh --sim-only   # Rust core → ios/Frameworks/TranslatteFFI.xcframework + Swift bindings
(cd ios && xcodegen generate && open Translatte.xcodeproj)
scripts/ios/test-sim.sh                # XCTest on the simulator + one scripted translation, saved to out/ios/
scripts/ios/test-sim.sh models-cache path/to/photo.jpg ja
```

The simulator reads models straight from the host's `models-cache/`
(`SIMCTL_CHILD_TRANSLATTE_MODELS_DIR`); otherwise the app downloads them into Documents/models from its setup
and Languages screens, as on Android. `TRANSLATTE_E2E=1 TRANSLATTE_SIM_DEVICE=<erased simulator> scripts/ios/test-sim.sh`
adds a UI test that does that whole setup over the network. Device builds need a development team and the `increased-memory-limit` entitlement
(already in `Translatte.entitlements`; the app no longer strictly needs it).

The app loads the models and runs the translation model once (`Engine::prepare`) on launch and whenever the source
language changes, so a photo goes straight to OCR and translation.

## Android app

Requires the Android SDK (platform 35, build-tools 35), NDK, a JDK 17+, and `rustup target add aarch64-linux-android`.

```bash
scripts/android/build-app.sh            # translatte-ffi → jniLibs + Kotlin bindings, then the debug APK
adb -s emulator-5554 install -r android/app/build/outputs/apk/debug/app-debug.apk
```

The app ships no models: on first launch it downloads the detector and the language packs you pick
straight from their Hugging Face repos (WorkManager, with a foreground notification), and the Languages screen
adds or deletes them later. Downloads use rustls with Android's trust store via rustls-platform-verifier. Debug
builds take `--es autotest_download det,rec-latin,pair-fr-en` and `--es autotest_image <file in the app's external
files dir> --es autotest_from fr` on `am start`, the latter writing `autotest.json` beside the
photo; `run-as co.huggingface.translatte sh -c 'echo xet_data=debug > files/rust_log'` sets `RUST_LOG` (logcat
tag `translatte`).

## Live camera (experimental)

With "Live translation (experimental)" on in Settings (the default), the camera translates preview frames
continuously and paints English over the preview; the shutter freezes the latest live result into the result
viewer (or takes a photo when nothing has been translated yet). Each frame (raw RGBA plus a clockwise rotation, about
960x720) is read with `Engine::ocr_frame`, then translated from the source it was read as with
`Engine::translate_regions` while the next frame is read (only by the loaded pipeline, so after `unload` or a
source change the frame stays untranslated rather than loading models): OCR and translation sit behind separate locks, each stage holds at most one frame, and a frame read while the
translator is busy waits for it (`LiveStages`), with at most one frame start per second when the phone runs hot. Live
frames run OCR at fp16 (loaded by the first live frame), photos at fp32. A cache of recent translations, shared with photos, means only new text
reaches the translation model, and a block close to one of the last three frames' blocks in place (IoU ≥ 0.3) and
text (≤ 20% of characters changed, numbers unchanged) reuses that block's translation, so OCR jitter doesn't cost a
translation; a reused block is compared with the text that was actually translated, so matches don't drift.
Both apps keep the same rules in `LiveRules` and `LiveOverlayTracker`: a box matched to the same text stays and slides, an unmatched box disappears 500 ms after its last match (checked every 100 ms, so stalled updates don't leave it behind) or at once when a new box overlaps it, and a frame with no text clears the overlay. Debug builds show updates/s and per-stage
milliseconds on the camera and log each update; on Android, `scripts/android/live-stats.sh [seconds]` summarizes
them from logcat. The iOS simulator has no camera, so with `-mock-camera <image>` the still is fed as frames.

### Testing live mode with recorded clips

Debug builds can replay a video in place of the camera, at real time and aspect-filled like the preview, with
the clip's rotation applied: `-mock-video <path>` on iOS, `--es mock_video <path>` on Android (a file in the
app's external files dir; `--es mock_video_source <code>` picks the source language). It stops at the end and logs
`live replay done`, or loops with `-mock-video-loop YES` / `--ez mock_video_loop true`. Debug builds also log
each overlay update and box change (add, move, retext, remove with its reason) as `liveev {json}` lines (logcat tag
`translatte`, the iOS app's stderr and `Documents/liveev.jsonl`).

```bash
scripts/live/make-clip.py out/live/synthetic.mp4           # text pans in, holds, slides off (needs ffmpeg)
scripts/live/run-ios-sim.sh out/live/synthetic.mp4         # "iPhone 18 Pro" simulator
LIVE_SOURCE=ja scripts/live/run-android.sh clip.mp4        # connected device with the debug app installed
scripts/live/analyze.py out/live/ios-synthetic/liveev.jsonl --video out/live/ios-synthetic/screen.mp4
```

The run scripts save the screen recording, the log and `summary.json` under `out/live/`. The analyzer reports
update rate and stage times, flicker (a text hidden and shown again within 3s) and each text's visible fraction,
time to clear after a box's last match, churn, the most boxes at once, and frame age for replays; with `--video` it
extracts a frame per second into `frames/`.

## Android CLI smoke test

Cross-compiles the CLI for `aarch64-linux-android` (API 31) and runs the full pipeline on a device over `adb`. Requires the Android NDK (found under `$ANDROID_HOME/ndk/`, or set `ANDROID_NDK_HOME`), `rustup target add aarch64-linux-android`, `cmake`, `ninja`, `sccache`, and `adb`.

```bash
scripts/android/build.sh      # -> <target dir>/aarch64-linux-android/release/{translatte,libc++_shared.so}
scripts/android/run.sh core/tests/data/bonjour.png fr     # <image> <from> [-] [name]; "-" = OCR only
```

- NCNN builds from `ncnn/vendor/` via the NDK CMake toolchain with the NDK's OpenMP. On big.LITTLE phones OCR runs pinned to the big cores, one NCNN thread per big core (`TRANSLATTE_OCR_PIN=0` turns pinning off, `TRANSLATTE_OCR_THREADS` sets the thread count).
- bergamot-translator builds via the NDK CMake toolchain with `c++_shared` for `armv8.2-a+dotprod` (`BERGAMOT_BUILD_ARCH` overrides).
- `run.sh` pushes the binary, shared libs, manifest and the needed models (detector, the source language's recognizer pack, and its translation model unless OCR-only; models whose size is unchanged are skipped) to `/data/local/tmp/translatte/`, runs under `/system/bin/time -v`, and pulls `out/android/<name>.{png,json,log}`.
- `run.sh` knobs: `TASKSET=<hex cpu mask>`, `RUN_TIMEOUT` (seconds, default 60).
- Benchmarking on a phone: keep the screen on (`adb shell svc power stayon usb`) and the phone cool. A dozing or throttled Pixel 8 caps every cluster near 1.1GHz.
- TLS: `build.sh` builds with `--no-default-features --features tls-native` by default, or `TLS=rustls` (OpenSSL, vendored and built from source; needs `perl` and `make`, ~25s on a cold build). This backend is for testing only: the default `tls-rustls` verifies through `rustls-platform-verifier`, which needs JNI initialization that a bare `adb shell` binary can't do and panics without it. The app keeps rustls + the platform verifier (Android's trust store via JNI). native-tls reads Android's `/system/etc/security/cacerts` itself, so no CA setup is needed. Core enforces exactly one of `tls-rustls`/`tls-native` when `download` is on.
- On-device `fetch`: Xet-backed files need a writable `HF_XET_CACHE` (only a small staging dir is written; the chunk cache is off), since `HOME` is `/` under `adb shell`:

  ```bash
  adb shell 'cd /data/local/tmp/translatte && LD_LIBRARY_PATH=. HF_XET_CACHE=/data/local/tmp/translatte/xet-cache \
    ./translatte fetch --langs fr --models models --manifest manifest.json'
  ```

- On Android the CLI loads fonts from `/system/fonts` and exits via `_exit` after flushing stdout/stderr, skipping C++ static destructors.
